# Урок 23. Один кадр по HTTP (Этап 6. Камера)

Первый урок камеры. Задача — снять **один кадр** и увидеть его в браузере. Веб-сервер
здесь тот же, что в уроке 17, только вместо HTML с температурой отдаём JPEG-байты.

```
Браузер --GET /jpg--> ESP32-S3-CAM --> esp_camera_fb_get() --> JPEG --> Браузер
```

Перед этим уроком: [esp32cam_hardware.md](esp32cam_hardware.md) (плата, прошивка,
питание) и `pio run -e lesson_check_cam -t upload` — диагностика без сети.

## Что изучаем

| Понятие | Где в коде |
|---|---|
| **конфигурация камеры** | `camera_config_t` + `esp_camera_init()` |
| **жизненный цикл кадра** | `esp_camera_fb_get()` → отдать → `esp_camera_fb_return()` |
| **бинарный ответ HTTP** | `setContentLength()` + `client.write(fb->buf, fb->len)` |
| **кеш браузера** | `?t=Date.now()` в `src` картинки |
| **«видео из фото»** | галочка «непрерывно»: 2–4 к/с и понятно, почему не больше |

## Почему кадр — это JPEG, а не пиксели

`cfg.pixel_format = PIXFORMAT_JPEG` — сжимает **сам сенсор OV2640**, ESP32 в этом не
участвует. Разница принципиальная:

| Формат | VGA 640×480 |
|---|---|
| RGB565 (2 байта на пиксель) | 614 400 байт |
| JPEG | 20 000–40 000 байт |

Внутренней памяти у ESP32-S3 ~320 КБ на всё (heap). То есть **несжатый VGA-кадр физически не
влезает** — отсюда и PSRAM, и JPEG. Именно поэтому Этап 8 (компьютерное зрение)
будет жить на .NET-стороне: распознавать удобно там, где есть память.

`jpeg_quality` — счётчик грубости сжатия, **0..63, меньше = лучше и больше байт**
(не проценты!). Рабочий диапазон 10–12.

## PSRAM решает, какое разрешение доступно

```cpp
if (psramFound()) { frame_size = FRAMESIZE_VGA;  fb_count = 2; fb_location = CAMERA_FB_IN_PSRAM; }
else              { frame_size = FRAMESIZE_QVGA; fb_count = 1; fb_location = CAMERA_FB_IN_DRAM;  }
```

`fb_count = 2` — двойная буферизация: пока один кадр отдаётся в сеть, следующий уже
снимается. На одном буфере эти операции выстраиваются в очередь.

## Главное правило: возвращать буфер

`esp_camera_fb_get()` отдаёт **указатель на буфер внутри драйвера**, а не копию.
Пока буфер у нас, драйвер его не переиспользует. Забыли `esp_camera_fb_return()` —
через `fb_count` кадров `fb_get()` начнёт возвращать `NULL`, и «камера сломается»
без единой ошибки в логе. Это самая частая ошибка в камерных скетчах.

## Почему JPEG нельзя отдать через `server.send()`

`server.send(200, "image/jpeg", body)` принимает **строку**, а в JPEG есть нулевые
байты — строка обрежется на первом же. Поэтому:

```cpp
server.sendHeader("Cache-Control", "no-store");
server.setContentLength(fb->len);        // объявляем длину заранее
server.send(200, "image/jpeg", "");      // заголовки, пустое тело
server.client().write(fb->buf, fb->len); // байты — прямо в сокет
```

## Кеш браузера

Картинка по одному и тому же URL кешируется: второй раз браузер покажет ту же
фотографию, не сходив на плату. Лечится уникальным параметром — `/jpg?t=1730000000`.
`Cache-Control: no-store` на сервере — второй слой той же защиты.

## Эндпоинты

| URL | Что делает |
|---|---|
| `/` | страница: картинка, «Снять кадр», «непрерывно», ползунок вспышки |
| `/jpg` | один кадр JPEG |
| `/flash?v=0..255` | яркость вспышки (PWM, не `digitalWrite`) |
| `/info` | текст: разрешение, quality, PSRAM, heap, RSSI, счётчик кадров |

Вспышка через PWM на **канале LEDC 7**, а не 0: камера занимает `LEDC_CHANNEL_0` +
`LEDC_TIMER_0` под генерацию XCLK. Забрать у неё таймер = потерять картинку.

> На S3-платах пин подсветки не стандартизован, поэтому в `pins.h` стоит
> `CAM_FLASH_LED -1` и код подсветки не компилируется вовсе (ползунок и `/flash`
> остаются, но ни на что не влияют). Найти свой пин — «охота за LED» в
> `lesson_check_cam`; нашёл — впиши в `pins.h`, и всё оживёт само.

## Запуск

```bash
pio run -e lesson23_cam_snapshot -t upload
pio device monitor                 # напечатает IP -> открой http://<IP>/
```

Перед прошивкой в `lesson23_cam_snapshot.cpp` поставить свои `SSID` / `PASS`.

## Что проверить глазами

1. Кадр появился — камера и сеть работают.
2. Нажми «Снять кадр» несколько раз: в мониторе бегут строки
   `[HTTP] кадр #N: 640x480, 24 118 байт`.
3. **Размер байт «дышит»**: наведи на однотонную стену — меньше, на пёстрый ковёр —
   больше. Это и есть JPEG: цена кадра зависит от картинки, а не только от разрешения.
4. Включи «непрерывно» — получишь ~2–4 к/с. Каждый кадр здесь = **новый HTTP-запрос**
   (TCP-хендшейк, заголовки, ответ, закрытие). Урок 24 избавится от этих накладных
   расходов и даст 18–25 к/с на том же железе.
5. Если нашёл пин подсветки — покрути ползунок вспышки в темноте.
6. Открой `/info`.
