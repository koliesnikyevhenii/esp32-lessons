# Урок 25. Все возможности OV2640 (Этап 6. Камера)

Урок «пощупать датчик». К потоку из урока 24 добавляется панель, которая крутит
настройки камеры на живом видео — и сразу видно, что каждая из них делает с
картинкой и с к/с.

## Главная мысль урока

Настройки живут **не в нашем коде, а в самом сенсоре**. Драйвер отдаёт структуру
`sensor_t` с указателями на функции:

```cpp
sensor_t* s = esp_camera_sensor_get();
s->set_brightness(s, 1);      // записывает регистры OV2640 по шине SCCB
s->status.brightness;         // что записано сейчас
```

То есть `set_*` — это **команда чипу камеры**, а не фильтр в прошивке. Поэтому она
бесплатна по процессору: ESP32 пиксели не трогает вообще. Ч/б, негатив, сепия,
зеркало — всё делает сенсор на лету.

Это же объясняет, почему в Этапе 8 (компьютерное зрение) распознавание уедет на
.NET: сенсор умеет **менять** картинку, но не **понимать** её.

## Что где смотреть

| Группа | Параметры | Что увидишь |
|---|---|---|
| Размер и качество | `framesize`, `quality` | прямой обмен «детализация ↔ к/с ↔ битрейт» |
| Яркость и цвет | `brightness`, `contrast`, `saturation` | −2…+2, дефолт тусклее, чем хочется |
| Эффекты | `special_effect` | 0 нет, 1 негатив, 2 ч/б, 3 красный, 4 зелёный, 5 синий, 6 сепия |
| Геометрия | `hmirror`, `vflip`, `dcw` | понадобится, когда камера на роботе встанет вверх ногами |
| Баланс белого | `awb`, `awb_gain`, `wb_mode` | выключи `awb` под лампой накаливания — картинка «пожелтеет» |
| Экспозиция | `aec`, `aec2`, `ae_level`, `aec_value` | выключи `aec` и крути `aec_value` руками: 0 — чернота, 1200 — засвет |
| Усиление | `agc`, `agc_gain`, `gainceiling` | в темноте усиление вытягивает яркость **ценой шума** |
| Коррекции | `bpc`, `wpc`, `raw_gma`, `lenc` | битые/белые пиксели, гамма, коррекция затемнения по краям |
| Диагностика | `colorbar` | тестовые полосы вместо картинки |
| Подсветка | `flash` | только если нашёл её пин (на S3 в `pins.h` по умолчанию `-1`) |

`colorbar` — реально полезный инструмент: полосы генерирует сам сенсор и гонит по той
же шине данных. **Полосы есть, а картинки нет** → шина и драйвер в порядке, проблема
в оптике или свете. Полос тоже нет → проблема в шлейфе/питании.

`sharpness` у OV2640 **не поддерживается** — вызов вернёт −1, панель покажет
`unsupported`. Это нормально: у разных сенсоров разный набор.

## Пары «авто / руками»

Три пары работают по одному принципу: пока автоматика включена, ручное значение
игнорируется.

| Автомат | Ручная величина |
|---|---|
| `awb` (баланс белого) | `wb_mode` (нужен ещё `awb_gain = 1`) |
| `aec` (экспозиция) | `aec_value` 0…1200 |
| `agc` (усиление) | `agc_gain` 0…30 |

Отсюда рецепт для FPV: если картинка «дышит» яркостью при движении робота (автоматика
всё время переоценивает сцену) — зафиксируй `aec` и `agc` руками. Видео станет
стабильнее, хотя в тени темнее.

## Как это устроено в коде

Один эндпоинт на всё:

```
GET /control?var=brightness&val=1
GET /status                       -> JSON со всеми текущими значениями
```

В прошивке — таблица `strcmp` в `applyControl()`, возвращающая код сенсора
(0 = ок, −1 = не поддерживается). В браузере панель рисуется циклом из массива
`GROUPS` — иначе вёрстка на 25 контролов не влезла бы в флеш-строку.

`/status` читает **не наши переменные, а `s->status`**: там лежит то, что реально
записано в сенсор. Кнопка «перечитать /status» — способ убедиться, что твоё значение
доехало (а не только подвинулся ползунок).

## Что важно про `framesize`

Смена разрешения меняет размер кадра в середине MJPEG-потока — `<img>` от этого
залипает. Поэтому в панели после смены `framesize` поток переоткрывается через 300 мс.

## Запуск

```bash
pio run -e lesson25_cam_controls -t upload
pio device monitor          # напечатает IP -> открой http://<IP>/
```

В `setup()` сразу выставлены `brightness = 1` и `saturation = 1` — как в примере
CameraWebServer: из коробки OV2640 отдаёт заметно тусклую и бледную картинку.
Там же закомментированы `vflip` / `hmirror` — раскомментируешь, когда прикрутишь
камеру к машинке «неправильной» стороной.

## Что проверить глазами (мини-эксперименты)

1. `special_effect = 2` (ч/б): картинка серая, **битрейт заметно упал** — серому
   JPEG нужно меньше байт. Заодно это ответ на вопрос «зачем ч/б в машинном зрении».
2. `quality`: поставь 63 — картинка развалится на квадраты, но к/с вырастут; поставь
   4 — красиво, но кадры станут тяжёлыми и поток просядет.
3. Прикрой камеру рукой и смотри на `aec_value`/`agc_gain` при включённой автоматике,
   потом выключи `aec` и `agc` — сцена перестанет подстраиваться.
4. В темноте выкрути `agc_gain` в максимум: увидишь, как «яркость покупается шумом».
5. `hmirror` + `vflip` — переверни картинку.
6. `colorbar = 1` — тестовые полосы; потом обратно в 0.
7. `lenc = 0` — по углам кадра проявится затемнение (виньетка), которое обычно
   компенсируется сенсором.
